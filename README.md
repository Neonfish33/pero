# Перо

Тихий офлайн-редактор Markdown в духе iA Writer. Одна кодовая база на Flutter для Windows, Android и iOS.

Задача проекта — не повторить iA Writer буквально, а перенести его философию: минимум интерфейса, режим фокуса, режим печатной машинки, подсветка Markdown прямо в тексте, мгновенный отклик и полная работа без интернета. За основу взят прототип `pero.html`.

## Статус по этапам

- [x] Этап 1. Фундамент: проект, шрифты, темы, настройки, модель документа.
- [x] Этап 2. Редактор: подсветка Markdown, фокус, печатная машинка, статистика, горячие клавиши, автопродолжение списков.
- [x] Этап 3. Хранение: SQLite, библиотека документов, автосохранение, восстановление после перезапуска.
- [x] Этап 4. Предпросмотр и полировка: нативный предпросмотр, импорт/экспорт, экспорт HTML, гайд по Markdown, миграция старых документов, мобильные файловые диалоги, релизные сборки.

## Что сделано

### Набор текста

- Подсветка Markdown прямо в редакторе: заголовки, списки, цитаты, блоки кода, ссылки, жирный и курсив.
- Режим фокуса: приглушение всего, кроме текущего предложения или абзаца. Для строк списков, цитат и заголовков режим «Предложение» подсвечивает текущую строку.
- Режим печатной машинки: строка с курсором удерживается по центру экрана по вертикали. Запас по высоте сделан через `SingleChildScrollView` (padding 50% сверху и снизу), а не через `InputDecoration.contentPadding`, поэтому область ввода не сжимается и буквы не обрезаются. При изменении высоты окна строка перецентрируется.
- Автопродолжение маркированных и нумерованных списков по `Enter`.
- Undo/redo и системное выделение — нативные возможности Flutter.
- Три шрифта: IBM Plex Mono, Inter, Source Serif 4 (кириллица включена). Размер шрифта регулируется.
- Темы: светлая, тёмная, авто (по системе).
- Ширина колонки: узкая (680), обычная (860, по умолчанию), широкая (1040).
- Счётчик слов, символов и времени чтения; для выделения — отдельно.
- Горячие клавиши: `Ctrl/⌘ + B`, `Ctrl/⌘ + I`, `Ctrl/⌘ + E`, `Ctrl/⌘ + N`, `Ctrl/⌘ + F`.

### Документы

- Библиотека документов: создание, поиск, переименование через первую строку, удаление в два нажатия.
- Автосохранение в SQLite с задержкой (debounce ~450 мс), восстановление библиотеки после перезапуска.
- Приветственный документ при первом запуске.
- «Гайд по Markdown» — обычный документ с примерами разметки. Открывается кнопкой `?` в шапке списка документов или через меню `⋮` → «Гайд по Markdown».
- Импорт и экспорт `.md`, экспорт HTML, копирование Markdown и HTML в буфер обмена.
- Импорт резервной копии старой браузерной версии (JSON): документы с исходными ID и датами, без дубликатов; настройки шрифта, темы, фокуса и печатной машинки тоже переносятся.
- На Android и iOS экспорт Markdown и HTML открывает системное окно «Поделиться»; импорт использует системный выбор файлов с MIME-типами и UTI.

### Интерфейс

- Адаптивная раскладка: постоянный сайдбар на широком экране, drawer на узком.
- Верхняя панель (заголовок, меню, предпросмотр) прячется во время набора и возвращается при движении мыши.
- Нижняя панель (фокус, печатная машинка, шрифт, размер, тема, ширина колонки, статистика) видна всегда.
- Окно Windows открывается развёрнутым.

## Сборка под Windows

### Путь с кириллицей

Инструменты Flutter на Windows плохо переносят путь с кириллицей. Проект лежит в `C:\Users\yagan\Downloads\аналог ia writer\pero`, поэтому для сборки создан junction на короткое 8.3-имя папки (`IAWRIT~1`):

```
C:\src\pero -> C:\Users\yagan\Downloads\IAWRIT~1\pero
```

Собирайте из `C:\src\pero`. Если проект перенесут, junction нужно пересоздать.

```powershell
flutter build windows --debug
# результат: C:\src\pero\build\windows\x64\runner\Debug\pero.exe
```

### Релизная сборка (release)

`flutter build windows --release` через junction всё равно падает: MSBuild получает реальный длинный путь с кириллицей и не может прочитать `app.dill`. Release нужно собирать в отдельной ASCII-папке. Весь цикл автоматизирован:

```powershell
powershell -ExecutionPolicy Bypass -File tool/build_windows_release.ps1
```

Скрипт синхронизирует исходники в `C:\pero_build`, делает `flutter clean`, `pub get`, готовит junction-ссылки плагинов, собирает release и обновляет `dist/pero-windows-x64/` с архивом `dist/pero-windows-x64.zip`.

Вручную:

```powershell
robocopy "C:\Users\yagan\Downloads\аналог ia writer\pero" "C:\pero_build" /E /XD build .dart_tool .git ephemeral dist
cd C:\pero_build
flutter pub get
powershell -ExecutionPolicy Bypass -File tool/prepare_windows_links.ps1
flutter build windows --release
```

Готовый запускаемый комплект лежит в `dist/pero-windows-x64/` (`pero.exe` + DLL + `data/`). Его нужно запускать целиком из папки; отдельный `pero.exe` без соседних файлов не заработает. Там же лежит архив `dist/pero-windows-x64.zip`.

### Значок, метаданные и окно

- Своя иконка приложения: `windows/runner/resources/app_icon.ico` (размеры 16–256, серифная «П» на бумажном фоне). Она же показывается в панели задач и в Проводнике.
- Метаданные exe в `windows/runner/Runner.rc`: «Перо — редактор Markdown», версия берётся из `pubspec.yaml`. Поля `CompanyName`/`ProductName` намеренно оставлены `com.pero`/`pero`: от них зависит путь данных `%APPDATA%\com.pero\pero`, поэтому переименовывать их нельзя.
- Минимальный размер окна — 560×420 логических пикселей с учётом DPI; окно по-прежнему открывается развёрнутым, тёмная тема заголовка следует за системой.

### Открытие `.md` из Проводника

Приложение принимает путь к файлу в аргументах командной строки. Достаточно выбрать `pero.exe` через «Открыть с помощью» для `.md`, `.markdown` или `.txt` — файл будет импортирован в библиотеку и открыт. Постоянную ассоциацию файлов можно включить вручную или через будущий установщик.

## Сборка под Android (APK)

Собирается из ASCII-папки `C:\pero_build` (Gradle так же не любит кириллический путь). Нужны Android SDK, JDK 17+ и интернет: NDK `28.2.13676358` и CMake `3.22.1` Flutter доустанавливает сам (лицензии SDK должны быть приняты).

```powershell
cd C:\pero_build
flutter build apk --release   # или --debug
```

Результат — универсальный APK (arm64-v8a, armeabi-v7a, x86_64):

```
build/app/outputs/flutter-apk/app-release.apk
build/app/outputs/flutter-apk/app-debug.apk
```

Копии лежат в `dist/pero-release.apk` и `dist/pero-debug.apk`. Release подписан debug-ключом из шаблона — для установки на устройство и теста годится, для публикации в Play нужен свой ключ.

Текущие APK в `dist/` собраны из среза до версии 1.0.0 и не включают последние изменения — перед продолжением работы над мобильными платформами их нужно пересобрать.

В `android/app/build.gradle.kts` для release отключены `isMinifyEnabled` и `isShrinkResources`. Иначе R8 переименовывает `kotlin.coroutines.Continuation` и ломает suspend-методы Pigeon-плагинов: при запуске падает `PlatformException ... NoSuchMethodError ... SharedPreferencesApiRegistrar.getAll`. Для потери минификации на время теста это нормально; при выпуске понадобятся keep-правила ProGuard.

Установка на устройство: включить «Установка из неизвестных источников» и открыть APK, либо

```powershell
adb install dist\pero-release.apk
```

### Симлинки плагинов

Flutter создаёт симлинки для плагинов. Если сборка падает с сообщением `Building with plugins requires symlink support`:

1. Вариант без прав администратора — заранее создать junction-ссылки:

   ```powershell
   powershell -ExecutionPolicy Bypass -File tool/prepare_windows_links.ps1
   flutter build windows --debug
   ```

2. Либо включить режим разработчика (`ms-settings:developers`) и войти в систему заново, либо запускать сборку от администратора.

После `flutter clean` или `flutter pub get` junction-и могут понадобиться снова — повторно запустите скрипт.

## Миграция из старой браузерной версии

Старая версия хранит документы в `localStorage` браузера под ключом `pero`. Чтобы перенести их в «Перо»:

1. Откройте старую версию в браузере и выполните в консоли разработчика:

   ```js
   copy(localStorage.getItem('pero'))
   ```

2. Вставьте скопированный текст в файл, например `pero-backup.json`.
3. В новом приложении: меню `⋮` → «Импорт резервной копии (JSON)…» и выберите файл.

Импорт понимает старый формат `{docs: [{id, text, t}]}` и общий формат `{documents: [...]}`. ID и даты сохраняются, повторный импорт не создаёт дубликаты. Неизвестные настройки игнорируются, размер шрифта ограничивается диапазоном 13–30.
